1. Abstract

Every exam season a university must give each course an examination slot so that no student has two papers at the same time. This case study models the problem as graph coloring: courses are vertices, an edge joins two courses that share students, and a slot is a color. A backtracking algorithm assigns slots one course at a time and undoes choices that lead to a dead end, while a greedy first-fit method serves as a comparison. Both are implemented in C++ and tested on six cases, including edge cases. For an eight-course example both methods need three slots, and a crown-graph test shows greedy needing three slots where backtracking proves two are enough. An interactive solver lets the reader edit conflicts and watch the search.

2. Introduction and problem statement

A university offers many courses and students enrol in overlapping sets of them. If two courses share even one student, their exams cannot be held together. Fewer slots means a shorter exam period, so the university wants the smallest number of slots with no clash. Doing this by hand for hundreds of courses is slow and error-prone.

Problem statement: given a set of courses and the pairs that conflict, assign each course a slot so that conflicting courses never share a slot, using as few slots as possible, and show how the choice of algorithm affects the result.

4. Problem modelling

  • Input: number of courses n, a list of conflicting pairs, and the number of slots k available.
  • Output: a slot for every course (or a statement that k slots are not enough) and the minimum number of slots.
  • Representation: an n × n adjacency matrix where adj[u][v] = 1 if courses u and v share students. A slot is a color number 0 to k−1, stored in an array col[].
  • Constraint: if adj[u][v] = 1 then col[u] ≠ col[v].
  • Assumptions: conflicts are known in advance, all exams last one slot, rooms and invigilators are unlimited, and there are no self-conflicts.

5. Algorithm explanation

5.1 Backtracking (exact)

Take courses in order. For the current course try slots 0 to k−1. A slot is safe if no already-placed neighbour uses it. If safe, place the course and move to the next one; if the next course cannot be placed at all, undo (backtrack) and try the next slot. If every course is placed, we have a valid timetable. To find the minimum, try k = 1, 2, 3… and stop at the first k that works.

solve(v, k):
  if v == n: return true
  for c = 0..k-1:
    if safe(v, c):
      col[v] = c
      if solve(v+1, k): return true
      col[v] = -1          // backtrack
  return false

5.2 Greedy first-fit (comparison)

Take courses in order and give each the smallest slot not used by its neighbours. It is fast and never backtracks, but it can use more slots than necessary because early choices are never revised.

for v = 0..n-1:
  c = 0
  while some neighbour of v has slot c: c++
  col[v] = c

Why backtracking? It tests only choices that are consistent so far and abandons a whole branch the moment it hits a clash, which is far less work than trying every possible assignment.

6A. Worked example

Eight courses: DSA-II, DBMS, COA, OS, Maths, AI, Network, Physics. Clashing pairs (shared students): DSA-II–DBMS, DSA-II–COA, DBMS–COA, COA–OS, OS–Maths, Maths–AI, AI–Network, Network–Physics, OS–AI, DBMS–Network, DSA-II–Physics.

DSA-II, DBMS and COA all clash with each other (a triangle), so they need three different slots and fewer than three is impossible. Placing the remaining courses in order never needs an undo, giving:

Backtracking can in the worst case try every one of the kⁿ assignments, but pruning at each clash cuts most branches, which is why the 8-course example finishes instantly. Graph coloring is NP-complete, so no known algorithm is fast for every large graph; this is why real universities use heuristics for hundreds of courses.

9. Results and discussion
The solver found a valid three-slot timetable for the university example and proved two slots impossible because of the DSA-II, DBMS and COA triangle. With no conflicts one slot suffices, and with four mutually clashing courses four slots are required. Greedy matched the optimum except on the crown graph, where it used three slots against the optimal two.

10. Conclusion and limitations
Modelling exam scheduling as graph coloring turns a messy timetable problem into a clear algorithmic one. Backtracking guarantees the minimum number of slots on small inputs, while greedy gives a quick answer that is usually, but not always, optimal.
Limitation: the model ignores room capacity, invigilators and student fatigue, and backtracking becomes impractical for hundreds of courses. Improvement: order courses by number of conflicts (largest first) before coloring, or use the DSatur heuristic.

Viva preparation


Why is this a graph coloring problem?
Courses are vertices, shared students are edges, and slots are colors; two joined vertices must get different colors.


What does backtracking do when it hits a dead end?
It un-assigns the last course and tries its next slot, abandoning the whole branch that cannot work.


Why can greedy use more slots than needed?
It never revises early choices. In the crown graph its early picks force a third slot.


What is the minimum possible number of slots here?
At least the size of the largest group of mutually clashing courses (a clique). The triangle forces three.


Why is the worst case O(kⁿ)?
Each of n courses has k slot choices, so all assignments number kⁿ; pruning avoids most but not all of them.


Is a faster exact algorithm known?
No. Graph coloring is NP-complete, so large cases rely on heuristics.
